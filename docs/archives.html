Archives

Most Macintosh software you can download from the Internet arrives wrapped, sometimes in more than one layer. The end of a file's name tells you which wrapping it has, such as .hqx or .zip. This page explains the wrappings, how Mill lets you look inside them, and which programs open the rest.

Why Macintosh files are wrapped

A Macintosh file can have two parts, called forks. The data fork holds a document's contents, such as the words of a letter. The resource fork holds things the Macintosh uses, such as an application's menus, icons, and program code. The Finder also keeps information with each file, such as which application opens it.

Most other computers keep only one part for each file. A Macintosh file stored on one of them as it is would lose its resource fork and its Finder information, and an application without its resource fork doesn't work. So Macintosh files are usually wrapped before they travel.

There are three kinds of wrapping, and each has its own name. Encoding keeps a file whole. Compression makes a file smaller. An archive puts many files into one.

Encoding: keeping a file whole

Encoding puts both forks and the Finder information into a single file that any computer can store. Two encodings are common:

  • MacBinary, with names ending in .bin.
  • BinHex, with names ending in .hqx. A BinHex file is written entirely in ordinary text characters, so it can also travel in e-mail and newsgroups, which are made for text. It is usually about a third larger than the same file in MacBinary.

Both encodings have been in use since 1985.

Compression: making a file smaller

Compression makes a file smaller, so it takes less time to download. When the file is unpacked, it comes back exactly as it was.

gzip, with names ending in .gz, compresses one file. It is common on Unix workstations, and it is described in RFC 1952, published in 1996.

A server can also compress a page with gzip before sending it, to save time on the way. Mill unpacks such a page as it arrives, and you see the page as usual.

Archives: many files in one

An archive holds many files in a single file, and it can hold folders too. Most archives are also compressed. Software usually arrives as an archive: an application, its Read Me, and its documents, packed together.

These are the archives you are likely to find:

  • StuffIt, ending in .sit, the most common kind for Macintosh software.
  • Compact Pro, ending in .cpt, also made for the Macintosh.
  • Zip, ending in .zip, common on IBM PCs.
  • tar, ending in .tar, common on Unix workstations. A tar archive isn't compressed, so it is often compressed with gzip afterward, and its name ends in .tar.gz.

An archive can also be self-extracting, with a name ending in .sea. A self-extracting archive is an application: double-click it, and it opens itself, with no other program needed. Because it is an application, it needs its resource fork, so it usually travels encoded, as .sea.bin or .sea.hqx.

Layers

Wrappings stack, and a file's name lists them in order. A file named game.sit.hqx is a StuffIt archive that was then encoded in BinHex. To unwrap it, work from right to left: decode the BinHex, then open the StuffIt archive.

Opening a wrapped file in Mill

Mill opens five of these wrappings itself: MacBinary, BinHex, gzip, Zip, and tar. When you click a link to one of them, Mill shows a small window that names the file, says what kind it is and how large, and offers three buttons:

  • Save... saves the file just as it came, the way Mill saves any download. This is the usual choice, so it is the one Return presses.
  • Browse shows what is inside, as a list, without saving anything.
  • Cancel does neither.

The list shows each file inside with its name, its size, its size as packed, and the date it was last changed. A folder inside the archive opens to its own list. Click a file in the list, and Mill shows it if it is a page, text, or a picture Mill can show. Otherwise Mill offers to save it, and the file you save is the one inside, unwrapped.

Each file inside has an address of its own: the archive's address, then #/ and the file's name inside the archive, as in http://server/kit.zip#/docs/readme.txt.

Browsing never changes the archive, and Save... always saves the file as the server sent it. The one exception is MacBinary: if Decode MacBinary is on in the Settings page, Mill decodes a MacBinary file as it saves it, as it always has.

When Browse is dimmed

MacBinary, BinHex, and gzip files hold one file each, and Mill can show what is inside as the file arrives, from any server.

A Zip or tar archive is different. To list one without saving it, Mill reads it a part at a time, out of order, and not every server does that well. File servers on the network at your school or office do it well, so Mill browses archives there in place. With Web and FTP servers, Mill saves the archive first and then shows its list: Browse is dimmed, a line in the window says why, and you check Browse after saving before you click Save....

Each protocol that can read part of a file has a setting, Support Random Access, under its name in the Settings page. Turn it on for a protocol if its servers answer well, and Mill will browse archives from them in place.

A .tar.gz file is opened in two steps. Browse the gzip file, and its list shows the tar archive inside. Save that, with Browse after saving checked, and Mill shows the tar archive's list.

Try this

This looks inside, then downloads, Compact Pro, by Bill Goodman, from the Macintosh software archive kept by FUNET, the Finnish University and Research Network. The file is about 122K, and it has two layers: a self-extracting archive, encoded in MacBinary.

  1. Type http://ftp.funet.fi/pub/mac/arcers/compact-pro-134.bin and press Return.
  2. Mill shows its window for a MacBinary file. Click Browse.
  3. Mill lists the one file inside, Compact Pro Package, with its size. Choose Back from the Go menu.
  4. Click Save..., choose a folder, and click Save.
  5. In the Finder, open the folder you chose and double-click the file. It is the self-extracting archive. It opens itself and asks where to put what's inside.

You now have Compact Pro, a program for opening and making Compact Pro archives. Compact Pro is shareware: you may try it for free, and if you keep using it, you pay its author the fee its documents ask for.

Programs for the rest

For the archives Mill doesn't open, use a program made for them. Many Macintosh software archives offer these programs, often in MacBinary, which Mill decodes for you.

StuffIt Expander, a free program made by Aladdin Systems, opens StuffIt and Compact Pro archives, and it can undo several layers at once. Mill marks the StuffIt files it saves so that StuffIt Expander opens them when you double-click them.

Mill's wrappings come from its Archive Formats Plug-In. If you installed Mill with Minimal Install, it has no such Plug-In, and Mill saves every wrapped file as it is, without the window.

Disk images

Some software comes as a disk image, with a name ending in .image, .img, or .dsk. A disk image is a copy of a whole floppy disk. Apple's Disk Copy program makes a real floppy disk from it, and Mill marks the disk images it saves so that Disk Copy opens them.
