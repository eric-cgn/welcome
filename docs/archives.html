Archives

Most Macintosh software you can download from the Internet arrives wrapped, sometimes in more than one layer. The end of a file's name tells you which wrapping it has, such as .hqx or .sit. This page explains the wrappings, what Mill does with each, and which programs open the rest.

Why Macintosh files are wrapped

A Macintosh file can have two parts, called forks. The data fork holds a document's contents, such as the words of a letter. The resource fork holds things the Macintosh uses, such as an application's menus, icons, and program code. The Finder also keeps information with each file, such as which application opens it.

Most other computers keep only one part for each file. A Macintosh file stored on one of them as it is would lose its resource fork and its Finder information, and an application without its resource fork doesn't work. So Macintosh files are usually wrapped before they travel.

There are three kinds of wrapping, and each has its own name. Encoding keeps a file whole. Compression makes a file smaller. An archive puts many files into one.

Encoding: keeping a file whole

Encoding puts both forks and the Finder information into a single file that any computer can store. Two encodings are common:

  • MacBinary, with names ending in .bin.
  • BinHex, with names ending in .hqx. A BinHex file is written entirely in ordinary text characters, so it can also travel in e-mail and newsgroups, which are made for text. It is usually about a third larger than the same file in MacBinary.

Both encodings have been in use since 1985.

When you download a file in MacBinary, Mill decodes it as it saves it. What you get is the Macintosh file itself, whole, and Mill says so at the bottom of its window: Saved "name", decoded from MacBinary. To have Mill save MacBinary files without decoding them, choose Preferences from the Edit menu and turn off Decode MacBinary.

Mill saves a BinHex file as it is, and marks it so that StuffIt Expander, a free program described below, opens it when you double-click it.

Compression: making a file smaller

Compression makes a file smaller, so it takes less time to download. When the file is unpacked, it comes back exactly as it was.

gzip, with names ending in .gz, compresses one file. It is common on Unix workstations, and it is described in RFC 1952, published in 1996.

When a .gz file holds a page, a text file, or a picture that Mill can show, Mill unpacks it as it arrives and shows it. Mill saves any other .gz file as it is. A server can also compress a page with gzip before sending it. Mill unpacks that page as it arrives, and you see the page as usual.

Archives: many files in one

An archive holds many files in a single file, and it can hold folders too. Most archives are also compressed. Software usually arrives as an archive: an application, its Read Me, and its documents, packed together.

These are the archives you are likely to find:

  • StuffIt, ending in .sit, the most common kind for Macintosh software.
  • Compact Pro, ending in .cpt, also made for the Macintosh.
  • Zip, ending in .zip, common on IBM PCs.
  • tar, ending in .tar, common on Unix workstations. A tar archive isn't compressed, so it is often compressed with gzip afterward, and its name ends in .tar.gz.

An archive can also be self-extracting, with a name ending in .sea. A self-extracting archive is an application: double-click it, and it opens itself, with no other program needed. Because it is an application, it needs its resource fork, so it usually travels encoded, as .sea.bin or .sea.hqx.

Layers

Wrappings stack, and a file's name lists them in order. A file named game.sit.hqx is a StuffIt archive that was then encoded in BinHex. To unwrap it, work from right to left: decode the BinHex, then open the StuffIt archive.

Try this

This downloads Compact Pro, by Bill Goodman, from the Macintosh software archive kept by FUNET, the Finnish University and Research Network. The file is about 122K, and it has two layers: a self-extracting archive, encoded in MacBinary.

  1. Type http://ftp.funet.fi/pub/mac/arcers/compact-pro-134.bin and press Return.
  2. Mill asks where to save the file. Choose a folder, and click Save.
  3. When the download is done, Mill says Saved "compact-pro-134", decoded from MacBinary. Mill has removed the first layer.
  4. In the Finder, open the folder you chose and double-click compact-pro-134. It is the self-extracting archive. It opens itself and asks where to put what's inside.

You now have Compact Pro, a program for opening and making Compact Pro archives. Compact Pro is shareware: you may try it for free, and if you keep using it, you pay its author the fee its documents ask for.

Looking inside an archive

Programs for the rest

For formats Mill doesn't open, use a program made for them. Many Macintosh software archives offer these programs, often in MacBinary, which Mill decodes for you.

StuffIt Expander, a free program made by Aladdin Systems, opens StuffIt archives, Compact Pro archives, and BinHex files, and it can undo several layers at once. Mill marks the StuffIt and BinHex files it saves so that StuffIt Expander opens them when you double-click them.

Other free programs open the rest, such as UnZip for Zip archives, suntar for tar archives, and MacGzip for gzip files.

Disk images

Some software comes as a disk image, with a name ending in .image, .img, or .dsk. A disk image is a copy of a whole floppy disk. Apple's Disk Copy program makes a real floppy disk from it, and Mill marks the disk images it saves so that Disk Copy opens them.
