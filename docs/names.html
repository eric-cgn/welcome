Names and Numbers

In Addresses, you read the name of a server: welcome.1in1e6.com. Names are for people. The computers on the Internet find each other by number. This page explains how Mill turns a name into a number, and what the other number you sometimes see in an address means.

Numbers for computers

Every packet carries the number of the computer it is going to. As you read in Rules of the Road, routers relay packets from one computer to the next; the number is how each router knows which way to send a packet.

Your Macintosh writes a computer's number as four smaller numbers, each from 0 to 255, separated by periods: for example, 192.0.2.1.

The number is called an IP address. IP stands for Internet Protocol, the protocol that carries packets across the Internet, described in RFC 791, published in 1981. An IP address is a different thing from the addresses you type into Mill, so this guide calls it a number.

Names for people

Numbers suit computers, but they are hard for people to remember, so servers also have names. Before Mill can send a request to welcome.1in1e6.com, your Macintosh needs the number that goes with that name. It asks a computer called a name server, which looks up the number and sends it back. All of this happens before the page begins to arrive.

Your Internet provider, or the people who run the network at your school or office, tell you which name server to use. Its number is set in the MacTCP control panel, or in the TCP/IP control panel on newer system software.

Name servers all over the Internet work together to keep track of names and their numbers. Together they are called the Domain Name System, or DNS, described in RFCs 1034 and 1035, published in 1987.

A name is read from right to left, from the general to the specific. The groups of names are called domains: com is a large domain, 1in1e6.com is our domain within it, and welcome.1in1e6.com is a name we chose within ours. Some endings tell you who a name belongs to: names ending in edu belong to colleges and universities in the United States, and names ending in gov to government bodies in the United States.

Ports

One server can speak more than one protocol. The same computer might send Web pages and Gopher menus, for example. To keep the requests apart, the server waits for each protocol's requests at its own numbered port.

Each protocol has a usual port, agreed on so that both computers know where to meet: 80 for the Web, 70 for Gopher, and 119 for newsgroups. When an address doesn't name a port, Mill uses the usual one for its protocol. That is why you rarely type a port.

Addresses that name a port

Now and then, a server uses a port other than the usual one. Its address then names the port: a colon and the port number come right after the server's name.

Try this

Type http://welcome.1in1e6.com:80/contents.html and press Return.

Mill opens the Contents page, the same page as http://welcome.1in1e6.com/contents.html. The :80 names the usual port for the Web, so it changes nothing. To come back to this page, click Names and Numbers in the list.
